## Overview

This game tries to combine REST APIs for standard user/game operations with WebSockets and background task scheduling for real-time combat.

### Core Domains

The project is split into domain-specific Django apps:

- **`fkdauth`**: User registration, login, and authentication tokens.
- **`mmo`**: Worlds, creatures, player stats, equipment, inventory, leveling, and real-time combat.
- **`market`**: Player-to-player marketplace for listing, buying, and selling items safely with database transactions.

I used several engines to calculated and refresh the game state: `mmo/services/` (`FightEngine`, `PlayerEngine`, `DropEngine`, `PlayerInventoryEngine`). Views, WebSocket consumers, and Celery tasks interact directly with these engines.

---

## Architecture: REST vs. WebSockets

- **REST (Django REST Framework)**: Used for on-demand actions that do not require real-time streaming:
  - Authentication (Login / Register)
  - Character creation and fetching player profile
  - Marketplace operations (listing items, searching deals, buying items)
- **WebSockets (Django Channels + Daphne)**: Real-time combat:
  - Once a fight is locked, both player attacks and creature attacks are constantly being processed.
  - Monster attacks are scheduled asynchronously with Celery (`countdown`), ticking everytime independently of the player. So if the player don't flee or kills the creature probably will die.
  - Updates the fight status to the client.

## Background Tasks (Celery)

Several recurring and event-driven tasks run in the background:

- **`monster_attack`**: Triggers independent monster counter-attacks during active fights.
- **`respawn_creatures`**: Repopulates worlds with creatures up to each world's limit.
- **`recover_player_status`**: Gradually recovers health and stamina for idle players.
- **`clean_orphan_items`**: Cleans up unowned items dropped over 24 hours ago.

## Getting Started

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) and [Docker Compose](https://docs.docker.com/compose/)
- (Optional for local running) Python 3.12+, Node.js 20+

### 1. Environment Setup

Copy `.env.example` into `.env`:

```bash
cp .env.example .env
```

Adjust the database credentials and secret key if needed.

### 2. Run with Docker Compose

Start the database, Redis, backend, worker, and scheduler:

```bash
docker compose up --build
```

Services running:
- **Postgres**: `localhost:5432`
- **Redis**: `localhost:6379`
- **Backend (Daphne/ASGI)**: `http://localhost:8000`
- **Celery Worker & Beat**: Running in background containers

### 3. Run the Frontend

From the `frontend` folder:

```bash
cd frontend
npm install
npm run dev
```

The frontend will start on `http://localhost:5173`.

## Running Tests

The backend includes test coverage for APIs, WebSocket combat flows, and Celery tasks.

To run tests locally:

```bash
cd backend
python manage.py test
```

Or run inside the Docker container:

```bash
docker compose exec fduel python manage.py test
```
